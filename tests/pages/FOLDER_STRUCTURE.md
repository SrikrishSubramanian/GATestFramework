# Tests/Pages Folder Structure

## Organization

```
tests/pages/
├── ga/
│   ├── components/          ← All POM files for GA components
│   │   ├── buttonPage.ts
│   │   ├── textPage.ts
│   │   ├── accordionPage.ts
│   │   └── ... (150+ POMs)
│   │
│   └── locators/            ← All locator JSON files
│       ├── buttonPage.locators.json
│       ├── textPage.locators.json
│       ├── accordionPage.locators.json
│       └── ... (150+ locator files)
│
├── locators/                ← Root-level locator files
│   └── (shared/root POMs)
│
└── loginPage.ts             ← Root-level POM
```

## How It Works

1. **POMs** load locators from `../locators/` directory
   - Example: `tests/pages/ga/components/buttonPage.ts` 
   - Loads: `tests/pages/ga/locators/buttonPage.locators.json`
   
2. **Locator Registry** resolves paths using:
   ```typescript
   const registry = loadLocators(path.join(__dirname, '../locators/fileName.locators.json'));
   ```

3. **All locators centralized** in `/locators` directories for easy management

## File Naming Convention

- POM files: `<componentName>Page.ts`
- Locator files: `<componentName>Page.locators.json`
- Match: buttonPage.ts ↔ buttonPage.locators.json

## Generation

Locator JSON files are generated by:
1. `playwright-agent` scanning live DOM or source code
2. Creating multi-strategy confidence-scored locators
3. Saving to respective locators/ folders

## Validation

All paths are:
- ✅ Consistent across all POMs
- ✅ Relative (no hardcoded absolute paths)
- ✅ Easy to locate and maintain
- ✅ Ready for automated generation
